# memory-tools（跨会话记忆使用范式）

记忆库是这个 agent 跨会话积累的知识面：偏好、事实、约定、纠正、教训、
洞见、画像。本技能定形何时写、何时查、如何引用。

## 工具面一图

| 工具             | 语义                   | 关键纪律                                   |
| ---------------- | ---------------------- | ------------------------------------------ |
| `memory_write`   | 主动记一条持久知识     | 无绕过合并的写路径；写前密文扫描命中即拒写 |
| `memory_search`  | 唯一跨会话检索入口     | query ≥3 字符；记忆条目 + 历史会话两段呈现 |
| `memory_read`    | 按 id 读条目全文与状态 | 需要全文/冻结/留存细节时用                 |
| `memory_forget`  | 软删除一条             | 冻结条目拒删；`promotedToSkill` = 晋升搬家 |
| `memory_restore` | 恢复已退场条目         | 管理面对账用                               |

## 何时写（memory_write——主动性纪律）

用户表达**持久有效**的知识时立即落库，不等用户明说「记住」：

- **preference 偏好**：用户口味（「回复别那么长」——含风格旋钮类表述）。
- **fact 事实**：环境与项目事实（「这个仓的测试跑 vitest」）。
- **convention 约定**：协作约定（「commit 信息用中文」）。
- **correction 纠正**：用户纠正了我的行为（「下次别动 lockfile」）——纠正类
  是最高优先级入库项，同类错误重复即自进化失败。
- **failure 教训**：踩坑结论（某命令在此环境不可用的实证）。
- **insight 洞见**：非显然的推断结论。
- **profile 画像**：用户画像级信息（惯用栈、时区习惯）。

参数纪律：`summary` 是合并与冲突判定的比较面（一句话、可比较）；`content`
是注入用全文；`confidence` 0..1 缺省 0.8；`scope` project 需当前会话在项目内；
`validFrom`（ISO UTC）标注「该事实自何时成立」，写在未来 = 前瞻知识（到点
前读面不可见）；同主题既有条目会被合并管线自动吸收——重复陈述不怕写，怕
不写。含密文（token/密钥/口令）的内容会被拒写——敏感串不属于记忆库。

## 何时查（memory_search——先查后行）

- **会话开局**：先按当前任务关键词查一轮，带出既有偏好/约定/教训再动手。
- **决策前**：方案二选一时查是否已有相关 convention/failure。
- **报错后**：先查此错是否已有教训条目（同坑不踩第二遍是底线）。

引用正账：检索命中并在答复中实际用上的条目，在正文里带 `[m:短id]`
引用（如「按既有约定 [m:ab12] …」）——引用即记账，长期不用的条目自然
退场；引用错了（条目已过时）如实写 corrected 引用，负账同样计入进化。

## 管理面语义（forget/restore）

- `memory_forget` 软删除：条目退场但可恢复；**冻结条目拒删**（受保护知识）。
- `promotedToSkill` 参数 = 晋升搬家：某条知识已固化进技能时，用它把源条目
  退场并记终态 `skill:<技能名>`——知识迁入技能、记忆库不留双份。
- `memory_restore` 恢复误删；对账走 `/memory` 管理面（人读全景）。

## 自检环（会话收尾前过一遍）

- 本会话用户给出的持久性表述是否都已入库（尤其 correction 类）？
- 本会话开局的 memory_search 是否真跑了（而非凭印象行动）？
- 正文中的 [m:短id] 引用是否都是本轮实际依据的条目？
